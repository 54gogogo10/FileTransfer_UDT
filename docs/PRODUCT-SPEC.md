## 1. 产品定位

### 1.1 一句话定位

面向局域网的点对点文件传输工具：**单文件免安装**，全程 SHA-256 完整性校验，覆盖「日常互传 → 增量备份 → 弱网/无回传链路 → 无头自动化」全谱系场景。

### 1.2 目标用户

| 用户群 | 典型需求 | 主要功能面 |
|--------|----------|-----------|
| 家庭 / SOHO 多机用户 | 电脑之间快速互传大文件 | GUI 发送/接收、进度卡片、断点续传 |
| 手机 ↔ 电脑 | 手机上传/下载电脑文件，无需装 App | HTTP 共享 + 二维码扫码 |
| 开发者 / 运维 | 定时增量备份、脚本化收发、无人值守接收 | CLI `sync`/`send`/`recv`/`verify`、监控模式 |
| 弱网 / 单向链路环境 | 高丢包 Wi-Fi、无回传链路（如单向网闸侧） | UDT 传输、单向 UDP + 多轮重发 + FEC |
| 离线内网 | 数据不出局域网、可控可审计 | 全程局域网内传输、配对码/加密/IP 过滤 |

### 1.3 核心价值主张

1. **完整性优先** —— 每个文件带 SHA-256 并在接收端重算比对；服务端对续传偏移、完成判定拥有权威；对「结果未知却报成功」零容忍。
2. **免安装单文件** —— 逻辑层 + UI 编译为单个 exe，UDT 原生库嵌入运行时提取；不写注册表（除可选的开机自启）、无服务、无驱动。
3. **协议谱系完整** —— 同一套线协议跑在三种传输上：TCP（通用）、UDT（可靠 UDP 流，弱网）、裸 UDP 单向（多轮重发 + Reed-Solomon 前向纠错，无回传链路）。
4. **隐私与可控** —— 数据只在局域网内流动；更新源强制 https；接收侧具备认证、确认、过滤三层控制。

### 1.4 设计原则（产品工程宪法）

- **判错方向不对称**：凡是「一致 / 不一致」类判定（摘要缓存、续传扫描），必须把误判方向设计成「多读一次 / 多传一次」，绝不允许可静默漏报。
- **失败关闭（fail-closed）**：安全门（接收确认、IP 过滤坏条目、压缩采样失败、HTTP 访问）在异常时一律倾向拒绝。
- **向后兼容**：新协议特性必须携带能力协商或降级路径，旧对端可继续互通；配置键迁移必须幂等且保留旧键镜像。
- **逻辑层与 UI 严格分层**：逻辑层零 UI 依赖且可脱离框架编译——这是多平台路线（§9）的地基。
- **测试即规格**：任何行为修复必须以测试钉住（判别验证：去掉修复该测试必须变红）。

## 2. 使用场景

| # | 场景 | 功能组合 |
|---|------|----------|
| S1 | 两台电脑日常互传单个大文件 | GUI 发送 + 并发分块 + 断点续传；中断后自动重试续传 |

| S3 | 每晚把工作目录备份到家里的小主机 | CLI `sync`（任务计划程序/cron）或 GUI 同步模式——重复发送只传差异 |
| S4 | 手机临时取电脑上的文件 / 上传照片 | HTTP 共享：浏览器列目录、上传、Range 断点下载、扫码直达 |
| S5 | 监控一个「落料」目录，文件出现即自动发出 | 监控模式：拷贝完成检测 + 队列自动让位 |
| S6 | 高丢包无线链路传大文件 | UDT 传输（可靠 UDP 流 + 库内拥塞控制） |
| S7 | 只有单向可达的链路（回包到不了） | 单向 UDP 发送：多轮重发 + RS 前向纠错，接收方「落盘即状态」 |

| S9 | 核对接收库是否被事后篡改/损坏 | 文件库校验（scrub）或 CLI `verify` |
| S10 | 批量串行发送一批文件后自动关机 | 发送队列 + 完成后动作 |

## 3. 功能规格

### 3.1 传输协议与模式

| 协议 | 传输层 | 回传链路 | 配对码/加密/压缩 | 断点续传 | 适用 |
|------|--------|----------|------------------|----------|------|
| TCP | 可靠字节流 | 有 | 全部支持 | 0x03 / 0x04 / 分块覆盖率续传 | 通用、防火墙友好 |
| UDT | 可靠有序 UDP 流（STREAM） | 有 | 全部支持（线协议同 TCP） | 同 TCP | 高丢包链路 |
| 单向 UDP | 裸 UDP 数据报 | **无** | **不支持**（无握手通道，帮助文案明示） | 「落盘即状态」：重发即续传 | 单向链路、极简接收端 |

**通用传输行为**（三协议共用，除非注明）：

- 发送端必须为载荷计算 SHA-256 并随包发送；接收端重算比对，不一致即判失败，不得落盘半成品到最终路径（临时文件 + 校验 + 原子改名，v2.12+）。
- 文件名冲突处理：在扩展名前追加 `_1`、`_2`……；文件夹冲突对根目录名追加。
- 接收前磁盘预检：可用空间 ≥ 声明大小 + 64MB 余量；声明大小 > 1 PiB 或为负必须拒绝（探测失败放行，不卡传输）。
- 限速：发送侧 `SpeedLimit`、接收侧 `RecvSpeedLimit`（KB/s，0=不限），令牌桶实现，接收限速靠流控反压发送方；**所有分块（含最后一块）都必须过限速**。
- 进度事件节流 100ms；ETA 超过 1 小时以 `h:mm:ss` 显示。
- 源端口可选绑定；绑定失败属可重试错误。

**单文件并发分块（0x02）**：

- 1–8 路并行连接（默认 4），单文件按声明偏移切分等大分块；每个 0x02 头带 16 字节 groupId。
- 完成判据必须是**已接收区间的覆盖**（区间合并排序后覆盖 `[0, size)`），不得按字节累加——重叠/重复块不得制造假完成。
- 瞬断重试：对 IOException 重试至 3 次尝试（分块按偏移写入是幂等的）。
- 暂停/继续（v2.14）：继续时先发 `0x0B` 覆盖率查询，服务端从内存 tracker 直答合并区间，客户端对补集补发；查询失败/旧对端回退全量重发。
- **源文件已变化则必须换新 groupId 全量重发**——0x02 无整文件哈希，按旧覆盖补发新内容会把两个版本拼成混合文件。
- 单个连接声明的合并区间数超 8192 拒收（慢速 DoS 守卫）；分块组装完成后服务端必须现算整文件摘要登记入缓存（供去重/scrub/0x04 跳过识别）。

**断点续传（0x03 单文件 / 0x04 文件夹）**：

- 协商应答 `0x10`：服务端偏移**权威**（取 max(客户端声明, 服务端实际)）；服务端无状态时从 0 开始。
- 会话绑定对端 IP + 文件名并加 per-session 锁（防跨连接劫持/并发写坏文件）。
- 完整校验（verifyFlag=1）：完整哈希必须在**建连之前**算完（大文件先算哈希再连接，否则对端接收超时掐断）；服务端收完重读比对，不一致删除文件回 status=3，客户端必须作废本地缓存摘要后重试（失配自愈）。
- 0x04 清单在建连前构建；支持按文件跳过（0x0A/0x1A 能力帧，服务端经摘要缓存逐文件回 1 字节）：清单中段插入/改动文件不再把其后同内容文件整份重发。
- 陈旧前缀保护：扫描遇到「大小相符但属旧版本完整文件」时不得拼接续传（用缓存已知摘要区分半截文件与旧完整文件）；校验失败的文件必须真删除并告知发送方。
- 0x04 完成判决走带内 1 字节（TCP，v2.13+）或带外 ACK（UDT），杜绝「正文之后服务端才失败、客户端仍报成功」。

**同步模式（增量备份）**：

- 文件夹模式子选项；发送走 0x04 + 由 (源路径, 目标地址) 确定性派生的**稳定会话 ID**（大小写/尾斜杠不敏感）——CLI `sync` 与 GUI 同步可互相接力。
- 重复同步只传差异；**本地删除的文件服务端保留**（增量备份语义）。
- 服务器侧不落盘进度——磁盘文件本身就是状态；会话可经「同步会话」对话框枚举、两步确认后整目录重置（含摘要前缀失效）。

**去重与摘要缓存**：

- `DuplicateFiles=skip` 时：0x00 收完与 basePath 已有文件比对（大小 + 全文件哈希）相同则删除新副本；0x03 命中已有文件直接回 status=2 零传输。
- `FileHashCache`（键 = 路径+大小+mtime）：客户端/服务端进程级实例 + 追加式日志持久化（带 FNV-1a 行校验，坏行丢弃）+ TTL 过期（`HashCacheDays` 默认 7 天，0=永不）+ strict 绕行（`SyncVerifyContent`）+ 两代分代淘汰 + 8MB 日志重写收敛；不可写时静默退化为内存缓存。
- 缓存免费填充路径：校验通过时、0x00/0x04 整文件接收时（行内哈希即完整摘要）、0x02 组装完成后。

### 3.2 发送侧功能

| 功能 | 规格 |
|------|------|
| 发送队列 | 串行批量执行；逐项快照面板参数；失败自动重试 `QueueRetries`（0–5，默认 1）次；列表持久化（`queue.txt`，上限 500 项，`|` 分隔——该字符在 Windows 文件名非法）；**完成后动作**：无 / 关机（`shutdown /s /t 60`，可 `shutdown /a` 取消）/ 休眠 / 执行命令，执行前弹确认 |
| 群发 | 复选已知设备 + 在线设备 + 手输 IP:端口（IPv4/v6 校验；重复地址只勾不重加）；并行对每目标起独立客户端（按面板协议/限速/配对码）；逐目标进度卡片；汇总 `{ok}/{total}` 并通知；可整体取消 |
| 监控模式 | `FileSystemWatcher` + 启动全量扫描；**拷贝完成检测**：独占打开（FileShare.None）成功 + 500ms 大小稳定窗口双重判定——半截文件与「0 字节占位后填充」不得发出；**未就绪文件在队列中后移一个位置**（队首让给下一个文件，本文件下一轮重试，不阻塞队首）；已消失文件直接丢弃；未就绪日志按文件节流（首报立即、后续 60 秒一次）；成功后移入「已发送文件/」（重名追加序号） |
| 文本互传 | 0x06，UTF-8 ≤1MB；接收侧弹非模态对话框（复制按钮）+ 气泡通知；历史落盘 200 条重启不丢 |
| 拖放 | 多文件/文件夹拖入逐项入队并打开队列对话框；单文件填充路径框 |
| 自动重试 | `AutoRetry`（默认开）：单文件首次即走 0x03（空文件回退 0x00——0x03 拒绝 0 字节），失败退避重试共 3 次尝试、跨尝试复用会话续传；文件夹失败后转 0x04 |
| 暂停/继续 | 单连接与并发分块发送中可用；取消型暂停（OCE），快照面板参数 + 会话 ID；继续按 0x03/0x04/分块补集分派 |
| 单向 UDP 专属 | 多轮重发 `UdpPasses`（1–5，轮间 400ms，进度按轮加权）；START/END 各连发 3 份（间隔 40ms）；FEC `UdpFecParity`（1–8，默认 2，`UdpFec=0` 关闭） |

### 3.3 接收侧功能

- **三协议标签页**（v2.14+）：TCP / UDT / UDP 各自独立的绑定地址多选（族通配 + 具体网卡，每勾选地址一个监听器）、端口、**保存目录**（`SaveDirTCP/UDT/UDP`，旧单键 `SaveDir` 首启自动迁移、三页初始同值）；可同时运行、独立启停；标签头 `●` 标记运行态。
- **运行中不锁配置**：某协议启动后仅该页的绑定/端口/目录冻结，其他协议页随时可改。
- **端口冲突检测**（v2.14+）：启动前逐地址预检——进程内同传输监听（TCP 独立；UDT × 裸 UDP 同用 UDP 传输互斥）+ OS 精确探测（族独立）；冲突弹窗逐地址列出，全被外部进程占用时保留「换下一可用端口」提议。
- **接收选项**（对话框；目录类选项下次服务器启动生效，有提示）：

  | 选项 | 键 | 规格 |
  |------|-----|------|
  | 接收前确认 | `ConfirmReceive` | `off`（默认，不确认）/ `unknown`（已知设备放行，其余弹 30 秒确认框）/ `all`（一律确认）；无应答视为拒绝（失败关闭）；同 IP 10 分钟内免重复弹窗 |
  | IP 过滤 | `IpFilterMode` + `IpFilterList` | off / allow / deny；条目支持精确地址、`192.168.1.*` 通配、CIDR（v4/v6 各自前缀比对，跨族永不匹配）；坏条目不匹配（fail-closed） |
  | 按设备分目录 | `PerDeviceFolder` | `<保存目录>/<设备名>/`；已知设备按记忆名解析，未知回退 IP |
  | 重复文件 | `DuplicateFiles` | rename（默认）/ skip |
  | 接收限速 | `RecvSpeedLimit` | KB/s，0=不限；下次服务器启动生效 |
  | 摘要缓存有效期 | `HashCacheDays` | 默认 7 天，0=永不；过期条目按未命中重算（「定时刷新」） |
  | 同步逐字节核对 | `SyncVerifyContent` | 开启即完全绕过两侧摘要缓存（strict），双侧生效 |
  | 配对码位数 | `PairingLength` | 4–12 位，默认 6 |

- **接收文件管理**：「打开目录」（当前选中标签页的目录）/「最近接收」（内存 100 条）；按日期归档 `AutoArchive`。
- **设备记忆与发现**：传输成功记入已知设备（`Name|Ip|Port|flags`，上限 10 条）；UDP 广播发现（`0xD1`→`0xD2`，默认端口 45000，响应含 TCP/UDT/需配对标志位，仅 IPv4）；已知设备管理对话框（使用/删除/清空）。
- **统计与历史**：`stats.log` 追加式（>2MB 重写保留末 5000 行）；今日/7 天/累计聚合 + 按设备明细；历史对话框按方向筛选、资源管理器定位、导出 CSV（UTF-8 BOM）；「全部清除」危险按钮双视图同步。

### 3.4 HTTP 共享

- 手写 HTTP 服务器（TcpListener，无 URL ACL/管理员要求）；共享**当前选中标签页**的保存目录；默认端口 8090。
- 浏览器（手机即可）：目录列表、上传（multipart 流式解析，落到所浏览子目录）、下载（Content-Length + RFC5987 中文文件名 + **Range 断点续传**：206/416，`Accept-Ranges: bytes`）、删除单个文件（无 JS 确认页 + 表单 POST + CSRF 双重校验）。
- 访问控制：配对开启时复用配对码；`?t=` 兼容书签/脚本，会话仅靠 HttpOnly + SameSite=Strict Cookie；按来源 IP 计错锁定（10 次 / 10 分钟，成功清零）。
- 加固上限：并发 32 连接（满则停 accept）、请求头 15 秒空闲超时、整请求 4GB / 单文件 2GB；统一 `Cache-Control: no-store` + `X-Frame-Options: DENY` + CSP；仅图片/音视频/pdf/txt 内联，HTML/SVG 一律 attachment。
- 启动即弹二维码（多网卡地址下拉，选择记忆 `QrAddress`）；共享运行期可随时重开；随主窗口关闭停止。

### 3.5 文件库校验（scrub）

- GUI「校验」：一次聚合扫描**全部已配置保存目录**（去重、仅存在的根）；逐文件重算 SHA-256 与摘要缓存比对；四类结论（一致 / 不一致 / 无记录 / 无法读取）；带进度条、可中途停止；缓存按自身规则作答（TTL 过期→无记录，strict 开→全部无记录）。
- CLI `verify --dir`：同一引擎；**发现不一致退出码 1**；无记录不算失败。

### 3.6 CLI 无头模式

| 动词 | 用途 | 关键参数 |
|------|------|----------|
| `send` | 发送单文件/文件夹 | `--ip --port [--tcp|--udt|--udp] --file/--folder [--code] [--limit] [--srcport] [--nocompress] [--noencrypt]`；`--udp` 仅单文件，`--passes 1-5`、`--fec-parity 1-8`、`--nofec` |
| `recv` | 无人值守接收 | `--port [--out] [--tcp|--udt|--udp] [--code] [--count N]`；`--udp` 起裸 UDP 接收器 |
| `sync` | 一次性增量同步 | `--folder --ip --port [--tcp|--udt] ...`；与 GUI 同步共享稳定会话 |
| `verify` | 文件库校验 | `--dir`；不一致退出码 1 |

- 退出码：0=成功，1=错误，2=用法。WinExe 经 `AttachConsole` 接管父控制台；已有 stdout 句柄（重定向）时不覆盖。
- 复用 GUI 同一逻辑层与 ClientFactory——CLI 与 GUI 行为必须一致。

### 3.7 桌面集成

| 功能 | 规格 |
|------|------|
| 托盘常驻 | 最小化隐藏到托盘；关闭窗口=隐藏+保存配置；仅托盘菜单「退出」真退出 |
| 完成通知 | 气泡 + 提示音（`NotifyEnabled`/`NotifySound`） |
| 防睡眠 | 传输/服务器运行期间 `SetThreadExecutionState` 引用计数；未配对的 End 钳制回零 |
| 主题 | 深 / 浅 / 跟随系统三态，实时跟随系统换肤（WM_SETTINGCHANGE）；色板 token 集中管理；Win11 Mica 可选（默认关，环境检测命中自动跳过） |
| 双语 | 中文 / English 运行时切换；传输中锁定切换；禁止内联三元（文案集中 L10N） |
| 自动升级 | GitHub Releases（默认源）或 key=value 清单 URL；必须 https（明文仅回环）；exe + `.sha256` 边车，换入前重校验；原子换入（旧 exe 改名 + 失败回滚）后重启；启动 3 秒后台静默检查；「跳过此版本」记忆 |

### 3.8 配置持久化

- `config.ini` 键值对；启动加载、退出保存；多实例并行运行（后保存者生效）。
- **备份自愈（v2.15+）**：保存走 `.tmp` → 复制现文件为 `.bak` → `File.Replace` 原子换入；主文件存在但不可读/解析为空时回退 `.bak`；**主文件缺失视为用户重置，不回退**。
- 迁移模式：新键写入一次（幂等守卫），旧键保留为降级镜像（`ServerPort`、`SaveDir` 等）。

## 4. 线协议规格（摘要）

完整字节布局以 [WIRE-PROTOCOL.md](WIRE-PROTOCOL.md) 为准；本节是产品级约束。

### 4.1 传输类型

| 类型 | 名称 | 说明 | 引入 |
|------|------|------|------|
| `0x00` | 单文件 | 头 + 载荷 + 32B SHA256 | 初版 |
| `0x01` | 文件夹 | 名 + 数量 + 逐文件（大小/相对路径/载荷/哈希）；`fileCount` 上限 1,000,000 | 初版 |
| `0x02` | 分块文件 | 16B groupId + 声明偏移/总大小；覆盖判完成 | 初版 / v2.14 组 |
| `0x03` | 单文件续传 | 会话 ID + 大小 + 声明偏移 + verifyFlag + 可选完整哈希；应答 `0x10` | v2.x |
| `0x04` | 文件夹续传/同步 | 清单 + `0x11` 协商；v2.13+ 带内完成判决；v2.13+ 按文件跳过 | v2.x |
| `0x05` / `0x15` | 配对码认证 | 恒时比较；失败按来源 IP 计数锁定（10 次成功清零）；未启用时宽容接受 | v2.x |
| `0x06` | 文本消息 | ≤1MB UTF-8；TCP 带内判决 / UDT 带外 ACK | v2.x |
| `0x07` / `0x17` | **旧版**加密认证 | 仅 ≤2.11 对端互通；密钥来自网线明文的码哈希（**无真正机密性**），服务端记弱加密警告 | v2.9 |
| `0x08` / `0x18` | 压缩协商 | 分段 deflate 装饰器；**仅在认证后接受**（防预认证内存放大） | v2.11 |
| `0x09` / `0x19` | 认证 ECDH 加密握手 | 临时 P-256 + PBKDF2(50k) + 双向 HMAC 确认；密钥只来自共享秘密 Z | v2.12 |
| `0x0A` / `0x1A` | 能力协商 | bit1 = 支持 `0x0B` | v2.13 |
| `0x0B` | 分块覆盖率查询 | 服务端从内存 tracker 直答合并区间 | v2.14 |
| TCP 完成确认 | — | `0x00`/`0x01`/`0x06`（v2.13+ 含 0x04）处理后回 1 字节：`0x01` 接受 / `0x00` 拒绝；仅对端被证明为新版时等待 | v2.12 |

前导帧组合顺序：认证（`0x09` 首选 → `0x05` 明文 → 旧版 `0x07`）在前、`0x08` 压缩在后；装饰器包裹顺序必须是 `encrypt(compress(plain))`（压缩在外层）。

### 4.2 单向 UDP 帧

公共头 20 字节 + `0x01` START / `0x02` DATA / `0x03` END / `0x04` PARITY（自描述，旧接收端按未知类型忽略，无需协商）。会话 ID 由 (文件名, 大小, mtime) 确定性派生——重发即重试，接收方跨重启续收。

### 4.3 版本互通矩阵

| 客户端 \ 服务器 | 新版 | ≤2.11 旧版 |
|-----------------|------|------------|
| **新版** | 全特性（0x09 加密 + 压缩 + 能力帧 + 完成确认） | `EncryptStrict=0`（默认）：降级 0x05 明文 + 关压缩，记日志；`EncryptStrict=1`：拒绝降级 |
| **≤2.11 旧版** | 服务端接受 0x07 并记弱加密警告；客户端发明的 0x07 仍可通 | — |

单向 UDP 的 PARITY 帧对新旧接收端都无需协商（旧端静默忽略，仅损失纠错能力）。

## 5. 安全规格

### 5.1 威胁模型

| 威胁 | 场景 | 防线 |
|------|------|------|
| 被动窃听 | 局域网抓包 | 0x09 会话密钥只来自 ECDH 共享秘密 Z，网线不出现任何可推出密钥的材料；AES-CTR + 截断 HMAC + 段序绑定（等长段重排/交换立即校验失败） |
| 主动中间人 | 不知配对码的攻击者篡改/重放 | 配对码做双向 HMAC 确认，猜码必须过 PBKDF2(50k) 拖慢；失败按 IP 锁定 |
| 恶意对端 | 伪造声明放大内存/磁盘、路径穿越 | 所有声明字段上限校验（§6）、`SanitizeRelativePath` + 全路径前缀校验、压缩段长上限、分块区间数上限 |
| 恶意 HTTP 客户端 | 扫码网络内的第三方 | 访问码失败锁定、Cookie-only 会话、CSP/XFO、HTML/SVG 强制下载、上传双上限、删除 CSRF 双校验、路径穿越防护 |
| 更新供应链 | 明文源/TOCTOU 换包 | 更新源强制 https（明文仅回环）；下载后 SHA256 校验 + **换入前重校验**；边车缺失/格式非法直接拒绝 |

### 5.2 明确的残余风险（如实告知用户）

- 6 位配对码存在离线爆破空间，受 PBKDF2 拖慢；**加长配对码即可消除**（支持至 12 位）。
- 单向 UDP 模式无认证无加密（协议上做不了质询握手）——只适用于可信链路，帮助文案必须明示。
- 旧版 0x07 路径（≤2.11 对端）不具备真正机密性；`EncryptStrict` 提供关闭它的开关。

## 6. 性能与容量规格

### 6.1 上限与守卫

| 项 | 值 |
|----|----|
| 单文件声明大小上限 | 1 PiB（`MaxTransferSize`），负值拒绝 |
| 磁盘预检余量 | 64 MB |

| 分块合并区间上限（0x02/0x0B） | 8,192 |
| 并发连接数（发送侧） | 1–8 |
| 压缩段长上限 / 最小压缩段 | 64 MB / 64 B |
| 加密分段 | ≤256 KB，截断 HMAC 16 B |
| UDP 接收会话表 | 64 会话（最旧逐出）；覆盖位集封顶 ≈128 MB（64 满声明会话） |
| UDP FEC 待恢复缓存 | 每会话 ≤4 组且 ≤256 KB（FIFO+字节预算逐出） |
| UDP 已投递抑制窗口 | 10 分钟 / 256 会话 |
| UDP 收缓冲 | 4 MB；孤儿 .part 清理 7 天 |
| 服务器续传孤儿清理 | 7 天未返回 |
| 长任务读窗口（哈希/扫描静默） | 5 分钟（普通读超时 30 秒） |
| HTTP 共享 | 并发 32、头读超时 15s、整请求 4GB、单文件 2GB |
| 配对码 | 4–12 位数字，默认 6；PBKDF2 50k 迭代；10 次失败/IP 锁定 |
| 摘要缓存 TTL | 默认 7 天（0=永不）；日志重写阈值 8 MB |
| 历史/队列/记忆 | 统计重写 5000 行；队列 500 项；文本历史 200 条；已知设备 10 条；最近接收 100 条 |

### 6.2 资源行为（设计要求）

- 缓冲：TCP 收发缓冲 4 MB；UDT 使用库默认（≈12 MB，8192 包）——不得对已打开的 UDT socket 设缓冲选项（会抛错）。
- 内存封顶设计点：UDP 覆盖位集、FEC 超块、摘要缓存分代、进度节流——不得随传输时长/文件数无界增长。
- 压缩策略：写前采样（≤64KB 试压，压后 ≤30% 才压整段），`Fastest` 级别；不可压缩数据**零膨胀**直传。内部实测参考：随机 64MB TCP 回环 1.4s → 0.3s；deflate 在半可压缩数据上最慢（≈16 MB/s）低于全随机（≈51 MB/s）——这就是采样阈值取保守值 0.30 的依据。
- 每传输独立错误描述（并发传输间无共享可变状态）；UI 派发节流 100ms。

## 7. 可靠性与错误处理规格

### 7.1 假成功防护清单（每条都有回归测试钉住）

| 风险 | 防护 |
|------|------|
| 接收方拒绝却报成功 | TCP 完成确认字节（0x00/0x01/0x06/0x04）；UDT ACK 严格化——EOF/错误/超时一律失败，结果未知 ≠ 成功 |
| 零填充文件被判完成 | 续传偏移服务端权威 + 覆盖判完成（非字节累加） |
| 半截文件出门（监控模式） | 独占打开 + 大小稳定双重探测 |
| 两个版本拼成一个文件 | 陈旧前缀不拼接（0x04）；源变化换新 groupId（0x02） |
| 下载校验后被替换 | 换入前重校验哈希（TOCTOU 封口） |
| 配置文件保存中途崩溃截断 | `.tmp` + `.bak` + `File.Replace` 原子换入 |
| 失败被吞成成功 | 并发/UDP 发送失败必须 rethrow，不得只发事件 |

### 7.2 异常语义

- `ObjectDisposedException` / `InvalidOperationException`（Stop/Cancel 期间的正常竞态）静默捕获；其余错误必须可见（日志 + 事件）。
- 取消必须保持「已暂停」语义（OCE 路径与失败路径区分）。
- C# 5 逻辑层禁止 catch 块内 await（CS1985）——用标志变量模式。

## 11. 非目标

以下是本产品**不做**的事（防止范围蔓延）：

- 公网直连 / NAT 穿透 / 中继——产品边界就是局域网（含 VPN 虚拟局域网）。
- 多源分发（BitTorrent 式）、P2P swarm。
- 文件元数据完整保留（NTFS ACL / 所有者 / 备用数据流）。
- 实时协同 / 在线编辑。
- 单向 UDP 模式的认证与加密（协议上不可行，明确降档而非隐患）。
- 替代专业备份工具的版本历史 / 快照（同步模式只做「与服务器当前差异」）。

| 升级 | `UpdateUrl` `AutoUpdateCheck` `SkippedVersion` |
| 其他 | `NotifyEnabled` `NotifySound` `DiscoveryPort` `FirewallHintShown`（开机自启走 HKCU Run 键，不入 config） |

### 12.2 默认端口

| 服务 | 默认 | 可配置 |
|------|------|--------|
| TCP / UDT / 单向 UDP 服务器 | 各 8080 | `ServerPortTCP/UDT/UDP` |
| HTTP 共享 | 8090 | `HttpSharePort` |
| 设备发现 | 45000 | `DiscoveryPort`（仅 IPv4 广播） |
